## 0. 먼저 — 제품이 무엇인가

코드(`src/main/resources/static/pages/`, `assets/js/sidebar.js`)를 확인한 결과, 이 제품은
"대출 계산기"나 "채권 추심 대장"이 아니다. 다음을 한 시스템에서 다룬다:

- **여신**: 대출 등록 → 상환스케줄(원리금균등·원금균등·만기일시) → 중도상환 → 만기연장/재약정 → 완제
- **채권**: 연체 판정(D+1)·경과기간 집계 → 기한이익상실 → 대손상각 → 법적절차(지급명령·압류·추심) → 상각채권 회수
- **수납**: 회차 청구 생성, 법정변제충당(법적비용 → 이자 → 원금), 회차별 부분납 추적, 은행거래 업로드·대사
- **회계**: 전표(일/월), 전표승인, 재무제표(재무상태표·손익계산서 + **영업이익 단계**), 자금일보, 미지급
- **멀티회사(멀티테넌트)**: 회사별 DB 분리 운영

즉 경쟁 카테고리가 두 개다:
1. **대부업 여신/채권관리 SW** — 우리는 이걸 포함하고 그 위에 **회계·재무제표**까지 얹음.
2. **범용 ERP/회계**(이카운트 등) — 우리는 이걸 **대부업 도메인에 특화**했다는 게 차별점.
   (채권번호를 공용키로 여신~수납~충당~상각~전표를 연결, 20% 상한 검증, 면세 대응)

**전략적 함의:** 우리의 진짜 강점은 "채권 건수가 사람 머리로 감당 안 되기 시작했고,
**법령 리스크(이율 상한·변제충당 순서)** 를 수기 계산으로 지고 있는 회사"에게 크다.
채권 몇십 건을 엑셀로 굴리는 곳에는 이 강점이 과할 수 있다.
→ **우선 공략은 최말단이 아니라 '중형(채권 300~1,000건, 추심까지 도는 곳)'.**

## 1. 타깃 세그먼트

> ⚠️ **미확인**: 국내 대부업체의 채권 건수 분포 통계를 아직 확보하지 못했다.
> 아래 구간은 렌터카 시절 페르소나 구조(소/중/대)를 채권 건수로 옮긴 **가정**이다.
> 금융위원회 대부업 실태조사 등으로 **실제 분포를 확인해 다시 잡아야 한다.**

### A. 소규모 (채권 ~300건)
- **현실**: 사장+직원 1~3명. 관리 대부분 **엑셀·수기**, 세무는 외부 기장.
- **페인포인트**: (1) 상환스케줄·잔여원금이 엑셀로 흩어져 미수이자 누락.
  (2) 연체이자를 수기 계산 → 일할 계산 실수. (3) 전표를 손으로.
- **지불의사(WTP)**: 낮음·가격 민감. (가정)
- **우선순위**: **2순위.** 수는 많지만 우리 차별점(법령 검증·회계 연동)의 가치를 덜 느낌.
  → **Lite/Basic로 유입 → 성장하면 업셀** 하는 깔때기 입구.

### B. 중형 (채권 300~1,000건) ← **우선 공략 1순위**
- **현실**: 연체 채권이 쌓여 **법적절차(지급명령·압류)를 실제로 돌리는** 단계. 직원 5~15명.
  엑셀 + 별도 회계(이카운트/세무사)를 병행해 데이터가 3~4곳에 흩어짐.
- **페인포인트**:
  (1) **변제충당 순서**를 사람이 판단 → 같은 상황에 다른 결과가 나옴.
  (2) 법적비용을 채무자에게 청구했는지, 얼마를 회수했는지 추적이 안 됨.
  (3) 기한이익상실·대손상각 시점 판단이 담당자 감에 의존.
  (4) 이자수익과 예금이자가 섞여 **본업으로 얼마를 벌었는지** 모름.
- **지불의사**: 중간~높음. 여러 도구를 하나로 합칠 수 있으면 지불 여력 있음. (가정)
- **우선순위**: **1순위.** 우리 차별점이 정확히 이들의 고통을 푼다.

### C. 대형 (채권 1,000건+ / 멀티 법인)
- **현실**: 전산 담당·회계팀 존재. 자체 시스템이나 SI 구축 SW. 멀티 법인/지점.
- **페인포인트**: 낡은 SI 유지보수비, 멀티회사 통합 재무 가시성, 감독당국 보고 대응.
- **지불의사**: 높지만 **의사결정 느리고 요구 많음**(커스터마이즈·보안·SLA).
- **우선순위**: **3순위(초기), 후기 성장 타깃.** 첫 1~2곳은 전략 고객으로 확보해 레퍼런스화.

> **요약 우선순위: 중형(1) → 소규모(2, 깔때기) → 대형(3, 선별 레퍼런스).**

## 2. 핵심 가치제안 (왜 이 ERP인가)

### 한 줄 메시지 (홈페이지 히어로용)
> **"대출을 넣으면, 장부까지 끝나 있습니다."**
> — 대부업에 딱 맞춘 ERP. 엑셀 3개, 회계 프로그램 따로 쓰던 걸 한 시스템에서.

### 차별점 (기존 방식·경쟁 대비)

| 비교 대상 | 그들의 방식 | 우리 차별점 |
|---|---|---|
| **엑셀·수기** | 채권대장·스케줄·수납이 파일 3~4개로 흩어짐. 재입력·누락·계산오류. | **채권번호 하나로** 여신~수납~충당~상각~전표가 전부 연결. |
| **계산기·수기 충당** | 입금이 들어오면 어디에 얼마를 넣을지 담당자가 판단. 사람마다 결과가 다름. | **법정변제충당 자동** — 법적비용 → 지연배상금 → 약정이자 → 원금. 상각채권은 원금 우선으로 자동 전환. |
| **범용 ERP** (이카운트 등) | 회계는 강하나 **대부업 도메인 지식 없음**(상환스케줄·기한이익상실·대손상각을 수작업 설계). | 대부업 **업무 흐름과 전표 규칙이 기본 내장.** 도입 즉시 대부업 회계가 돌아감. |
| **SI 구축 시스템** | 초기 수천만원, 유지보수 경직, 변경 느림. | 구독형(월정액), 지속 업데이트, 초기비용 낮음. |

### 구체 효용(카피 소재) — 전부 실제 구현된 기능
- **"연 20%를 넘길 수 없습니다"** — 계약 등록 시 약정이율 > 20%, 연체이율 > min(약정+3%, 20%)이면
  서버에서 저장을 막는다. 화면 검증만이 아니라 서비스 레이어에서 막는다.
- **"입금 한 줄이면 충당까지 끝"** — 법적비용 → 이자 → 원금 순 자동 충당. 회차별 부분납까지 기록.
- **"본업으로 얼마 벌었는지 보인다"** — 대출채권 이자는 영업수익(400101),
  예금이자는 영업외수익(400201)으로 계정을 갈라 영업이익이 따로 나온다.
- **"90일 넘은 채권을 먼저 보여준다"** — 연체 경과기간 1~30/31~60/61~90/90일 초과 구간 집계.
  90일 초과가 있으면 대시보드에 경고.
- **"면세 처리가 기본"** — 이자수익은 부가세 면세라 세금계산서·부가세 로직이 아예 없다.
  매입도 총액으로 비용 계상.

> **주의(과장 금지):** "완전 자동 회계"라고 쓰지 말 것. 자동전표가 '대기' 상태로 생성돼
> 승인 워크플로우가 필요할 수 있다. **"수납·기한이익상실·대손상각 시 전표를 자동 생성"** 정도의
> 검증된 표현만 사용.
>
> **법률 자문 아님을 명시할 것.** "법정변제충당을 자동 적용한다"는 기능 설명이지
> "이 시스템을 쓰면 법적으로 안전하다"는 보증이 아니다. 이 선을 넘으면 표시광고 리스크가 생긴다.

## 3. 요금제 전략

### 3-1. 시장 가격 레퍼런스
> ⚠️ **미조사**: 렌터카 시절 조사(렌트데스크·투어오피스 등)는 이 제품과 무관해졌다.
> **대부업 여신/채권관리 SW 경쟁사와 가격대를 새로 조사해야 한다.**
> 현재 확인된 유일한 유효 레퍼런스는 범용 ERP인 이카운트(월 4만원 + 가입비 20만원)뿐이다.
>
> 조사 액션: 대부업 협회 회원사가 쓰는 SW, 채권추심 전문 SW, 여신관리 패키지의 가격대.

### 3-2. 원가 구조 — 렌터카 시절 분석 그대로 유효
- **한계원가는 서버비 중심**. 멀티테넌트 = **회사당 DB 분리**(템플릿 DB 복제).
- **가정(미확인, 실측 필요):** 클라우드 VM+관리형 DB 월 10만~30만원대에서 초기 수십 테넌트 수용 가능
  → 테넌트당 실서버 원가 월 수천~1만원 수준 추정 → 그로스 마진 90%+ (SaaS 전형).
- 결론: **가격은 원가가 아니라 "가치·경쟁·지불의사"로 정한다.** 원가는 하한만 방어.

### 3-3. 제안 요금제 (관리 채권 건수 기반 월 구독) — 1차안

기본 원리: **"기본 월정액 + 채권 건수 포함분 + 초과분 건당 과금."**
건수 늘수록 건당 단가↓. 연납 시 2개월분 할인(약 16%) 제안.

| 티어 | 대상 | 포함 채권 | **월정액(잠정)** | 초과 건당 | 주요 범위 |
|---|---|---|---|---|---|
| **Lite** | 초소형 ~100건 | 100건 | **월 6만원** | +600원/건 | 여신·스케줄·수납·충당 (회계 기본) |
| **Basic** | 소규모 ~300건 | 300건 | **월 12만원** | +500원/건 | + 재무제표·영업이익·중도상환·만기연장 |
| **Standard** | 중형 300~1,000건 | 1,000건 | **월 39만원** | +300원/건 | + 기한이익상실·대손상각·법적절차·자금일보 |
| **Pro** | 중대형 1,000~3,000건 | 3,000건 | **월 79만원** | +180원/건 | + 멀티회사·우선지원 |
| **Enterprise** | 3,000건+ / 멀티법인 | 협의 | **별도 견적** | 협의 | 전용 지원·SLA·데이터이관 밀착 |

**과금 기준 정의(중요):** 포함 건수는 **살아 있는 채권**(정상·연체·해지) 기준.
상각·종료 채권은 조회용으로 남지만 건수에서 제외한다. 이걸 명시하지 않으면
"오래된 채권도 돈을 받느냐"는 분쟁이 생긴다.

**월정액은 렌터카 티어를 그대로 승계했다.** 가격 자체는 총괄이 이미 검토한 수치라 유지하고,
**단위만 차량 대수 → 채권 건수로 바꿨다.** 다만 아래는 반드시 재검토가 필요하다:

- **건수 구간이 실제 분포와 맞는지 모른다.** 채권 100건과 차량 20대는 업무량이 다르다.
  대부업은 채권 1건당 회차가 12~36개씩 붙으므로 데이터량이 채권 건수에 비례하지 않는다.
  → **회차(스케줄 행) 수 기준이 원가에 더 가까울 수 있다.** 실측 후 판단.
- **초과 건당 단가**(600/500/300/180원)는 렌터카 대당 단가를 건수 비율로 나눈 값이다.
  근거가 약하다.

### 3-4. homepage-dev 지침
- 홈페이지 요금제 페이지에는 **5티어 + 월정액**을 노출. (반영 완료)
- 초과 건당 단가·연납 할인은 작은 글씨 또는 "문의 시 안내".
- **"모든 요금 VAT 별도" 명시**, 가입비 **없음**("가입비 0원"을 차별화 포인트로).
  (우리 SaaS 이용료는 과세 대상이다. 고객사가 면세사업자라 매입세액 공제를 못 받는 것과는 별개.)
- Enterprise는 가격 대신 **"문의"** CTA.
- **미확정 표기**: 얼리버드 프로모션으로 시작 가능.

## 4. 도입/온보딩 절차

1. **① 문의/상담 신청** (폼: 회사명·관리 채권 건수·현재 사용 도구·연락처) → 건수로 티어 자동 추천.
2. **② 온라인 데모** (30분) — "대출 1건이 실행→수납→충당→전표→재무제표까지 흐르는" 시나리오 시연.
3. **③ 무료 체험 1개월** — 테스트 테넌트 제공. 실제 채권 몇 건 넣어보게.
4. **④ 데이터 이관 지원** — 기존 엑셀의 채권·상환스케줄·미수 내역을 초기 적재(밀착 지원).
5. **⑤ 정식 계약·개통** — 월/연 구독 선택.
6. **⑥ 온보딩 체크인** — 도입 후 1주/1개월 CS 점검.

> **이관이 렌터카보다 어렵다.** 차량은 한 대가 한 행이지만, 채권은 한 건에 회차가 12~36개 붙는다.
> 기존 상환스케줄을 그대로 가져올지, 원금·이율·시작일만 받아 **재생성**할지 정책을 정해야 한다.
> → **권장: 재생성.** 우리 엔진으로 다시 만들어야 이후 충당·정산이 맞는다.
> 단, 이미 받은 수납 실적은 그대로 옮겨야 하므로 잔여원금이 어긋나지 않는지 검증 절차가 필요하다.

## 5. 신뢰 요소

1. **무료 체험 1개월 + 약정 없음, 가입비 0원** — 진입 리스크 제거.
2. **데이터 이관 지원** — 이관이 도입의 가장 큰 장벽. "우리가 옮겨드립니다"가 강력한 소구.
3. **회사별 DB 분리** — 멀티테넌트 구조상 데이터가 물리적으로 갈린다.
   *(주의: "로그인 없이 API 접근 가능" 이슈가 남아 있으면 **보안 강조 카피를 쓰지 말 것.**
   대부업은 개인신용정보를 다루므로 렌터카보다 이 리스크가 훨씬 무겁다.)*
4. **제품 투명성** — 실제 화면 스크린샷·기능 목록.
5. **창업자 직접 응대** — 초기엔 밀착 지원이 강점.
6. **도메인 깊이 제시** — 20% 상한 검증, 변제충당 전략 분리, 일할/월할 혼합 정산.
   이런 디테일 자체가 "이 사람들 대부업을 안다"는 신뢰다.

> **홈페이지에 쓰면 안 되는 것:** 없는 고객 후기·로고, "완전 자동", 미적용 보안 인증,
> 미확정 가격을 확정처럼, **"이 시스템을 쓰면 법적으로 문제없다"류의 보증.**
