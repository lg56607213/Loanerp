## 0. 이 문서를 쓴 근거 (직접 확인한 것 / 미확인한 것)

**직접 확인한 제품 기능** — `src/main/resources/static/pages/`, `assets/js/sidebar.js` 화면 기준:
- **여신관리**: 대출등록, 대출현황, 상환스케줄, 중도상환, 만기연장·만기종료.
- **채권관리**: 연체현황, 채권현황, **기한이익상실**, **대손상각**, 미수관리, 법적절차, 상담등록.
- **수납관리**: 청구생성·청구서발행, 수납등록, 은행내역업로드.
- **회계**: 일일/매출/월 전표, 전표승인, 재무상태표·손익계산서, 일자별 입출금·자금일보, 미지급, 선수금.
- **총괄**: 기타계정관리, 내정보, 사용자관리, 이메일 보고서, 세무상담, 구독관리.

**직접 확인한 계산 로직** — `contract/support/`, `loan/repayment/` 기준:
- 상환방식 3종(원리금균등 PMT / 원금균등 / 만기일시), 월할 스케줄 + 일할(365일) 정산.
- 이율 상한 검증: 약정 ≤ 20%, 연체 ≤ min(약정+3%, 20%). **서비스 레이어에서 검증**.
- 변제충당: 일반 채권 = 법적비용 → 지연배상금 → 약정이자 → 원금 / 상각 채권 = 법적비용 → 원금 → 이자.
- 채권 상태 5종(정상·연체·해지·상각·종료), 연체 판정 D+1.

**미확인(홈페이지에 사실처럼 쓰면 안 되는 것)**:
- **대부업 SW 경쟁 지형** — 렌터카 시절 조사는 폐기했고 대부업 재조사를 아직 못 했다.
  "유일한", "국내 최초" 같은 표현은 근거가 없으므로 금지.
- 도입 고객 수·절감 시간·정확도 같은 **수치 실적** — 검증 데이터 없음. 수치 주장 전면 배제.
- 신용정보 조회 연동(NICE·KCB), 전자계약, 자동이체(CMS) 출금 — 화면상 미확인. 언급하지 않음.
- 보안 인증(ISMS 등) — 미확인. **대부업은 개인신용정보를 다루므로 렌터카보다 이 리스크가 무겁다.**

> **표시광고 리스크 주의**: "국내 1위", "100% 자동", "최저가" 같은 최상급·단정 표현 금지.
>
> **대부업 특유의 추가 리스크**: **"이 시스템을 쓰면 법적으로 안전하다"는 취지의 표현을 쓰지 말 것.**
> 우리는 "연 20% 상한을 검증한다", "법정변제충당 순서를 자동 적용한다"까지만 말한다.
> 준법 여부의 최종 책임은 대부업자에게 있다. 이 선을 넘으면 법률자문 유사행위·허위표시가 된다.
> 또한 **채무자(일반 소비자)를 자극하는 추심 강조 카피**(예: "확실하게 받아냅니다")는 쓰지 않는다.
> 브랜드 리스크가 크고 채권추심법 취지에도 어긋난다.

## 1. 히어로 카피 (헤드라인 + 서브카피)

### A안 — "장부까지 끝나는" (회계 차별점 강조 · 채택)
- **헤드라인**: 대출을 넣으면, 장부까지 끝나 있습니다
- **서브카피**: 대출을 등록하면 상환스케줄이 만들어지고, 수납을 입력하면 변제충당·전표·재무제표가
  자동으로 이어집니다. 연체 판정부터 기한이익상실·대손상각·법적절차까지 한 곳에서.
- **소구점**: 관리 담당이 이중 입력·수기 계산에 쏟던 시간을 없앤다.

### B안 — "계산 실수가 곧 법 위반" (리스크 회피 강조)
- **헤드라인**: 연 20%, 손으로 계산하고 계신가요
- **서브카피**: 약정이율·연체이율 상한을 시스템이 막고, 변제충당 순서를 자동으로 적용합니다.
  계산 한 번 틀리면 되돌리기 어려운 일이 됩니다.
- **소구점**: 대표가 가장 무서워하는 것 — 몰라서 저지르는 법 위반.

### C안 — "본업으로 얼마 벌었나" (손익 시야 강조)
- **헤드라인**: 이번 달, 본업으로 얼마 남았을까
- **서브카피**: 대출채권 이자는 영업수익, 예금이자는 영업외수익. 계정을 갈라 영업이익이 따로 나옵니다.
  대출잔액·연체율·회수율을 매일 대시보드에서.
- **소구점**: 대표가 채권 건전성과 손익을 한눈에 보고 판단한다.

> 권장: 메인은 **A안**(구조적 차별점=회계 자동화). B안은 광고 소재·랜딩 변형으로 강력하다 —
> 다만 공포 소구라 톤을 과하게 하면 역효과. C안은 스크롤 하위 배너.

## 2. 기능별 소구 카피

각 설명은 확인된 화면·로직만 서술. 대표·관리 담당이 쓰는 말로.

### 2-1. 여신관리
- **헤드라인**: 대출 한 건을 넣으면 회차가 전부 깔립니다
- **설명**: 원금·이율·기간·상환방식만 넣으면 회차별 원금·이자·잔여원금이 자동으로 만들어집니다.
  원리금균등은 PMT 공식으로 월납입액을 직접 계산하므로 따로 넣을 필요가 없습니다.
  중도상환은 일할(365일)로 다시 계산합니다.

### 2-2. 채권관리
- **헤드라인**: 정상·연체·해지·상각·종료, 상태가 색으로 보입니다
- **설명**: 연체는 납입예정일 다음날부터 자동 판정됩니다. 경과기간을 1~30 / 31~60 / 61~90 / 90일 초과로
  나눠 보여주고, 90일을 넘은 채권이 있으면 대시보드에 경고를 띄웁니다.
  기한이익상실과 대손상각은 **담당자가 직접 등록해야** 확정됩니다. 시스템이 알아서 걸지 않습니다.
  - *(주: '자동 추심'처럼 들리게 쓰지 말 것. 실제로 자동 트리거는 없고, 없는 게 의도된 설계다.)*

### 2-3. 수납·변제충당
- **헤드라인**: 입금 한 줄이면 어디에 얼마가 들어갔는지 남습니다
- **설명**: 법적비용 → 지연배상금 → 약정이자 → 원금 순으로 자동 충당됩니다.
  대손상각된 채권은 원금을 먼저 회수하도록 순서가 자동으로 바뀝니다.
  회차별로 미납·부분납·완납이 기록되어, 부분 입금도 추적됩니다.

### 2-4. 자동 회계·전표
- **헤드라인**: 수납을 입력하면 전표가 알아서 만들어집니다
- **설명**: 충당 결과 그대로 원금은 대여금, 이자는 이자수익, 연체이자는 연체이자수익으로 갈려 기표됩니다.
  현금이 실제 오갈 때 인식하는 현금주의 기준입니다.
  - *(주: 자동전표는 확인/승인 단계를 거치는 구조. "자동 생성 후 확인" 톤으로. 100% 무인 자동으로 과장 금지.)*

### 2-5. 재무제표·영업이익
- **헤드라인**: 마감 없이도, 오늘 기준 영업이익
- **설명**: 대출채권 이자(영업수익)와 예금이자(영업외수익)를 계정부터 나눠 두었습니다.
  차입금 이자와 법무비용은 영업비용이라 영업이익에 반영됩니다.
  세무사에게 넘길 자료도, 대표가 볼 손익도 같은 데이터에서 나옵니다.

### 2-6. 법적절차 (보조 섹션)
- **헤드라인**: 들인 법적비용, 얼마나 돌려받았는지까지
- **설명**: 사건별로 신청비용·추가비용·확인비용과 환입을 기록하고, 수납이 들어오면
  **가장 먼저 이 비용부터 충당**됩니다. 얼마를 쓰고 얼마를 회수했는지가 채권 단위로 남습니다.

### 2-7. 면세 대응 (짧게)
- **헤드라인**: 대부업은 면세, 그래서 부가세 화면이 없습니다
- **설명**: 이자수익은 부가가치세 면세(금융·보험 용역)입니다. 세금계산서 발행과 부가세 분리를
  아예 두지 않았고, 매입도 총액으로 비용 계상합니다. 쓰지 않을 화면을 붙잡고 있을 필요가 없습니다.

## 4. FAQ 후보 (10개)

> 대표가 실제로 묻는 순서(가격 → 이관 → 난이도 → **법령** → 보안 → 지원)로 배치.
> 대부업은 렌터카와 달리 **법령 질문이 상위**로 올라온다.

**Q1. 가격이 어떻게 되나요? 채권 건수에 따라 다른가요?**
A. 관리 채권 건수 기준의 월 구독제입니다. 살아 있는 채권(정상·연체·해지) 기준이며
상각·종료 채권은 건수에서 제외합니다. 자세한 금액은 요금제 페이지를 참고해 주세요.
*(주: 건수 구간은 1차안. planning 확정 후 교체.)*

**Q2. 지금 쓰는 엑셀 채권대장을 옮길 수 있나요?**
A. 보유하신 채권·상환스케줄·고객 자료를 기준으로 이관 방법을 함께 정리해 드립니다.
*(주: 스케줄은 그대로 옮기지 않고 원금·이율·시작일로 재생성하는 것이 권장 정책 — planning 문서 §4 참조.
"그대로 옮겨드립니다"라고 쓰지 말 것.)*

**Q3. 회계를 잘 몰라도 쓸 수 있나요?**
A. 대출·수납·지출을 입력하면 원금과 이자가 갈려 전표가 자동으로 만들어집니다.
회계 지식보다 평소 업무 흐름대로 입력하시면 됩니다.

**Q4. 법정 최고이율이나 변제충당 순서도 지켜지나요?**
A. 계약 등록 시 약정이율이 연 20%를 넘거나 연체이율이 min(약정이율+3%, 20%)을 넘으면 저장이 막힙니다.
수납 시 변제충당은 법적비용 → 이자 → 원금 순으로 자동 적용됩니다.
법 개정에 대비해 상한값은 회사 설정으로 관리합니다.
*(주: 여기서 멈춘다. "그래서 법적으로 안전합니다"를 붙이지 말 것.)*

**Q5. 대부업은 부가세 면세인데 세금계산서도 나오나요?**
A. 이자수익은 부가가치세 면세라 세금계산서를 발행하지 않습니다. 매입 항목도 부가세를 분리하지 않고
총액으로 비용 계상합니다. 대신 청구서를 출력해 드립니다.

**Q6. 연체가 쌓이면 시스템이 알아서 기한이익상실을 거나요?**
A. 아니요. 자동으로 걸지 않습니다. 90일을 넘은 연체는 대시보드에서 경고로 알려드리고,
실제 등록은 담당자가 직접 하셔야 확정됩니다. 대부업법상 사전통지 의무가 있어 통지일도 함께 기록합니다.

**Q7. 데이터는 안전하게 보관되나요?**
A. 고객 회사별로 데이터베이스를 분리해 관리합니다. 백업·접근 관리 등 구체 사항은 상담 시 안내드립니다.
*(주: 보안 인증 보유를 사실처럼 표기하지 말 것. 로그인 인증 이슈가 남아 있으면
대외 보안 카피는 **보수적으로**. 대부업은 개인신용정보라 리스크가 크다.)*

**Q8. 직원 여러 명이 같이 쓸 수 있나요? 권한을 나눌 수 있나요?**
A. 회사 내 사용자 계정을 만들어 함께 사용할 수 있고, 역할(회사관리자/매니저/직원)에 따라 권한이 나뉩니다.
기한이익상실·대손상각 등록은 매니저 이상만 가능합니다.

**Q9. 도입하면 세팅과 교육은 어떻게 하나요?**
A. 초기 회사 정보·계정과목·채권 등록을 함께 진행하고, 실제 업무에 쓰실 수 있도록 사용법을 안내해 드립니다.

**Q10. 계약 기간이나 해지 조건이 있나요?**
A. 부담 없이 시작하실 수 있도록 조건을 안내드립니다.
*(주: 약정/해지 정책 미확정. 확정 후 정확히 기재 — 자동연장·위약금은 전자상거래법 표기 의무 있음.)*

> 렌터카 때와 달리 **경쟁사·검색결과 확인을 아직 못 했다.** 네이버 검색광고/구글 키워드플래너로
> 검색량과 경쟁도를 반드시 검증할 것.

### 5-1. 핵심 키워드 (헤드/미드테일) — 미검증
| 키워드 | 의도 | 비고 |
|---|---|---|
| 대부업 ERP | 정보/도입 | 자사 강점 정중앙 |
| 대부업 관리 프로그램 | 도입 | 대표 키워드로 추정 |
| 채권관리 프로그램 | 도입 | 볼륨은 클 듯하나 경쟁·의도 분산 가능 |
| 여신관리 시스템 | 도입 | B2B 표현, 검색 의도 정확 |
| 대부업 회계 프로그램 | 도입 | 자사 차별점과 정확히 매칭 |

### 5-2. 롱테일 키워드 (전환 의도 높음) — 미검증
- 대출 상환스케줄 프로그램 / 원리금균등 계산 프로그램
- 대부업 연체 관리 / 연체이자 계산 프로그램
- 변제충당 순서 / 법정변제충당 프로그램
- 기한이익상실 관리 / 대손상각 회계처리
- 대부업 전표 자동 / 대부업 재무제표
- 대부업 최고이자율 20% 계산
- 소규모 대부업 관리 프로그램 / 대부업 엑셀 대체

> 콘텐츠 전략: 롱테일 각각을 블로그/서브페이지 주제로 1:1 매핑
> (예: "변제충당 순서, 손으로 하면 왜 어긋나는가").
> **단, 법령 해설 콘텐츠는 법률자문으로 읽히지 않도록 "저희 시스템은 이렇게 처리합니다" 톤으로.**

## 6. 신뢰·전환 요소

검증된 실적·고객 로고가 없으므로 **"실물을 보여주는 신뢰"**로 접근. 없는 것을 있는 척하지 않는다.

**A. 지금 당장 쓸 수 있는(사실 기반) 신뢰 요소**
1. **실제 화면 스크린샷/짧은 데모 영상** — 대시보드·채권현황·변제충당 결과·손익계산서.
2. **기능 체크리스트/비교표** — "엑셀 vs JDEND"로 무엇이 자동화되는지 표로.
   (경쟁사 실명 비교는 표시광고 리스크 → 회피)
3. **개발사가 직접 응대** — "만든 사람이 직접 상담·세팅합니다".
4. **도메인 깊이 노출** — 실제 상환스케줄 표, 변제충당 순서 표, 연체 경과기간 표를 그대로 보여주는 것
   자체가 가장 강한 신뢰다. (홈페이지 반영 완료)

**B. 리드 수집 퍼널 설계**
1. 히어로 CTA(상담) → 2. 기능 스크롤 → 3. FAQ로 이의 해소 → 4. 하단 반복 CTA + 간단 폼
   (회사명 / 관리 채권 건수 / 연락처 / 현재 사용 도구). 폼 필드 4개 이내.
2. **오프라인 연계**: 대부금융협회 회원사 대상 도입제안서 발송.
3. 채널별 UTM으로 유입 출처 추적.

**C. 향후 신뢰 자산**
- 첫 도입 고객의 후기/사례 (확보되는 대로. **없는 후기 창작 금지**).
- 사업자정보·대표자·연락처·환불/이용약관 명시(전자상거래법 표시의무).

## 7. homepage-dev / planning 에게 넘기는 확인 요청

1. **마케팅 도메인 확정** — 현재 `planbloan.co.kr`을 썼는데 이는 CORS 설정에서 가져온 값이다.
   플랜비대부는 **고객사**이지 ERP 판매사가 아니다. 마케팅 도메인이 이게 맞는지 총괄 확인 필요. **(중요)**
2. **요금 건수 구간·약정·해지 정책** (planning) → FAQ Q1·Q10, 요금제 페이지 확정.
3. **데이터 이관 정책** — 스케줄 재생성 vs 그대로 이관 → FAQ Q2 문안 강도.
4. **보안 현황** — 로그인 인증 이슈. 대부업은 개인신용정보라 **정식 오픈 전 인증/접근제어 정리 필수**.
5. **미보유 기능 확인** — 신용조회 연동, 전자계약, CMS 자동이체. 없으면 계속 언급하지 않는다.
6. **표시광고 검토** — 정식 오픈 전 최종 점검. 특히 **법령 준수 보증으로 읽힐 표현**이 없는지.
