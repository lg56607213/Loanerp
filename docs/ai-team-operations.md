## 2. 부여한 권한 (요약) — 상세는 각 `.md`의 "권한과 책임" 섹션

- **ERP 개발자**: ERP 코드 전권. 오류 자율 수정(단 기록+총괄 보고). **변경마다 GitHub `origin/main`에 요약 커밋+push.** (push 권한 검증 완료)
- **홈페이지 개발자**: 마케팅 홈페이지 로컬 우선 구축→추후 도메인/서버 구매. 잠정 가격 책정(기획과 논의). CS 게시판(CS와 논의).
- **CS 담당자**: 고객만족 최우선. 정식 배포 후 매일 9시 불만 보고 + 주/월 분석(자동보고는 스케줄러 설정 필요).
- **마케팅 담당자**: 온/오프라인 마케팅 방안·로드맵. 타깃 대부업체 리스트 취합(공개정보·적법성 유의).
- **기획자**: 경쟁사·서버비용·손익·이익극대화 분석, 분/반기/연 로드맵, 유입 분석.
- **QA 테스터**: **테스트 테넌트(test111/112/113)에 한해 CRUD 전권.** 실데이터 회사는 읽기만. (렌터카 테넌트 erp_company_* 는 폐기 결정 — sql/discard_rentcar_tenants.sql) 규모별 전수 테스트, 전표 누락·재무제표 정합성 점검, 실시간 이중 보고.

### 전사 공통 원칙
1. **결과물을 직접 확인하고 증거를 제시한다.**
2. **확인 못 한 건 "미확인/미검증"이라고 말한다.** (하지 않은 걸 했다고 하지 않는다)

### 회계 기준
- **현금주의** (현금 실제 수령 시 수익 인식). 국내 중소기업 실무 관행. 발생주의 아님.
- 테스트 페르소나: test111(소규모 채권<300건) / test112(중형 300~1,000건) / test113(대형 1,000건+), 2021~2026.8 영업 가정.
  ※ 대부업 전환에 맞춰 규모 기준을 차량 대수 → 채권 건수로 바꿨다. 기존 테스트 데이터는 재생성이 필요하다.
